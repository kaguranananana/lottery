## 🎯 功能需求

### 核心需求

我需要开发一个**抽奖活动展台接口**，对外提供两种抽奖服务：

#### 1. 普通抽奖

- **功能描述**: 用户指定活动ID进行抽奖
- **输入**: 用户ID + 活动ID
- **处理流程**:
  1. 调用应用层的抽奖流程服务
  2. 将返回的领域对象转换为DTO对象
  3. 补充必要的额外信息
  4. 返回统一的响应结果
- **输出**: 抽奖结果（包含中奖信息）

#### 2. 量化人群抽奖（智能匹配）

- **功能描述**: 根据用户画像自动匹配活动后抽奖
- **输入**: 用户ID + 规则树ID + 决策因子（如年龄、性别）
- **处理流程**:
  1. 先调用规则引擎决策用户可参与的活动
  2. 使用决策出的活动ID执行抽奖
  3. 对象转换
  4. 返回结果
- **输出**: 抽奖结果

### 非功能性需求

- **异常处理**: 所有异常都要捕获并转换为错误码，不能向外抛出
- **日志记录**: 关键节点需要记录日志（开始、成功、失败）
- **统一响应**: 成功和失败都返回统一的响应对象
- **防腐层**: 不能直接暴露领域对象，必须通过DTO传输

## 🏗️ 设计模式要求

### 1. 门面模式（Facade Pattern）

**需求说明**:

- 创建一个门面类来简化复杂的子系统调用
- 隐藏应用层、转换层等多个子系统的复杂性
- 对外提供简单、统一的接口

**设计要点**:

- 门面类应该是调用方的**唯一入口**
- 内部协调多个子系统的调用（应用层服务、对象转换器等）
- 处理异常、日志、数据转换等横切关注点
- 不包含业务逻辑，只做流程编排

**期望效果**:

```
外部调用方 → 门面接口（简单） → 内部复杂调用
                                  ├─ 应用层服务
                                  ├─ 对象转换
                                  ├─ 异常处理
                                  └─ 日志记录
```

### 2. 防腐层（Anti-Corruption Layer）

**需求说明**:

- 领域层和接口层使用不同的对象表达
- 通过对象转换隔离内部领域模型和外部接口
- 保护领域的完整性，不被外部需求污染

**设计要点**:

- **领域层**: 使用 VO（Value Object）表达领域概念
- **接口层**: 使用 DTO（Data Transfer Object）进行数据传输
- 两者之间通过转换层连接
- 字段命名可能不同（如领域层用 `uId`，接口层用 `userId`）

**防腐层的价值**:

- 领域模型变化不影响外部接口
- 外部接口变化不污染领域模型
- 可以对不同调用方提供不同的DTO结构

## 🛠️ 技术栈要求

### 对象转换框架: MapStruct

**为什么选择 MapStruct**:

- 编译期生成代码，零运行时开销
- 性能接近手动 get/set
- 类型安全，编译期检查
- 易于使用，通过注解配置

**需要实现的功能**:

1. **通用映射接口**: 定义一个泛型接口，可被多个转换器继承
2. **具体转换器**: 实现 VO 到 DTO 的双向转换
3. **字段映射配置**: 
   - 同名字段自动映射
   - 不同名字段手动配置（如 `uId` → `userId`）
   - 日期格式化等特殊转换
4. **批量转换**: 支持 List、Stream 等集合类型的批量转换
5. **Spring 集成**: 生成的转换器要能作为 Spring Bean 被注入

**关键注解**:

- `@MapperConfig`: 标记配置接口
- `@Mapper`: 标记转换器，配置 Spring 集成
- `@Mapping`: 定义字段映射规则
- `@InheritConfiguration`: 继承配置
- `@InheritInverseConfiguration`: 继承并反转配置

## 📝 详细需求说明

### 对象转换需求

#### 源对象（领域层）

- **对象名**: DrawAwardVO
- **字段**: uId, awardId, awardType, awardName, awardContent, strategyMode, grantType, grantDate
- **特点**: 符合领域命名习惯，如使用 `uId`

#### 目标对象（接口层）

- **对象名**: AwardDTO
- **字段**: userId, activityId, awardId, awardType, awardName, awardContent, strategyMode, grantType, grantDate
- **特点**: 
  - 符合外部接口规范，如使用 `userId`
  - 多了 `activityId` 字段（需要在门面层手动设置）

#### 转换要求

1. `uId` → `userId` (字段名不同，需要手动配置)
2. 其他同名字段自动映射
3. `activityId` 在转换时忽略，稍后在门面层设置
4. 支持反向转换（DTO → VO）
5. 支持批量转换（List<VO> → List<DTO>）

### 门面接口需求

#### 方法1: 普通抽奖

**方法签名**: `DrawRes doDraw(DrawReq drawReq)`

**实现步骤**:

1. 记录日志（开始）
2. 调用应用层 `doDrawProcess()` 执行抽奖
3. 检查抽奖结果，失败则返回错误响应
4. 提取领域对象 `DrawAwardVO`
5. 使用转换器转换为 `AwardDTO`
6. 手动设置 `activityId` 字段
7. 封装成功响应对象
8. 记录日志（完成）
9. 返回结果
10. 捕获所有异常，转换为系统错误响应

#### 方法2: 量化人群抽奖

**方法签名**: `DrawRes doQuantificationDraw(QuantificationDrawReq req)`

**实现步骤**:

1. 记录日志（开始）
2. 调用应用层 `doRuleQuantificationCrowd()` 执行规则决策
3. 检查规则决策结果，失败则返回错误响应
4. 从决策结果中获取活动ID
5. 调用应用层 `doDrawProcess()` 执行抽奖（使用决策的活动ID）
6. 检查抽奖结果，失败则返回错误响应
7. 对象转换（VO → DTO）
8. 手动设置活动ID
9. 封装响应对象
10. 记录日志（完成）
11. 返回结果
12. 异常处理

### 异常处理需求

**要求**:

- 所有方法必须用 try-catch 包裹
- 捕获所有类型的异常（Exception）
- 异常不能向上传播，必须转换为错误码
- 异常日志必须包含: 用户ID、活动ID/规则树ID、请求参数、异常堆栈

**原因**:

1. 统一错误处理，避免RPC框架序列化异常
2. 确保所有异常都被记录
3. 对外提供友好的错误信息

### 日志记录需求

**关键日志点**:

1. **开始**: 记录方法开始执行，包含关键参数
2. **成功**: 记录执行成功，包含返回结果（JSON格式）
3. **失败**: 记录失败原因，包含请求参数和异常信息

**日志级别**:

- 开始、成功: INFO
- 失败: ERROR

## 🎨 设计原则

### SOLID 原则应用

1. **单一职责原则 (SRP)**:
   - 门面类只负责流程编排
   - 转换器只负责对象转换
   - 应用层负责业务逻辑

2. **开闭原则 (OCP)**:
   - 通过泛型接口扩展新的转换器
   - 不修改已有代码，只需实现新的转换器

3. **依赖倒置原则 (DIP)**:
   - 门面类依赖接口而非具体实现
   - 使用 Spring 依赖注入

### DDD 分层原则

- **防腐层**: 接口层不直接暴露领域对象
- **层间隔离**: 通过 DTO 隔离领域层和接口层
- **领域完整性**: 领域对象不被外部需求污染

## 💡 开发建议

### 开发顺序

1. 先实现通用映射接口（IMapping）
2. 再实现具体映射器（AwardMapping）
3. 编译验证 MapStruct 是否正确生成实现类
4. 最后实现门面类（LotteryActivityBooth）
5. 编写测试验证功能

### 调试建议

- 查看 `target/generated-sources/annotations/` 中生成的 MapStruct 实现类
- 使用断点调试验证对象转换
- 查看日志输出验证流程

### 常见问题

1. **MapStruct 没有生成实现类**
   - 检查注解配置是否正确
   - 确保 Maven 编译正确
   - 查看编译日志是否有错误

2. **字段映射不正确**
   - 检查 @Mapping 注解配置
   - 确认字段名拼写正确
   - 查看生成的实现类代码

3. **Spring 注入失败**
   - 确认 componentModel = "spring"
   - 检查包扫描路径
   - 验证生成的类有 @Component 注解
